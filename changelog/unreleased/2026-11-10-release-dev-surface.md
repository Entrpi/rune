- **A build without debug assertions keeps its command line for the app, and an ambient OTEL endpoint no longer turns interaction timing on there:** a `--release`, `--profile perf` or shipped binary reads Rune's flags (`--snap`, `--script`, `--trace`, `--help`, ...) from its arguments only after the new `rune::dev_tooling()`, called first in `main`, or with `RUNE_DEV=1` set; otherwise every argument goes to `extra_args` untouched and Rune parses none of them, so none can make it exit. A loopback `OTEL_EXPORTER_OTLP_ENDPOINT` turns timing on in such a build only with `RUNE_DEV=1` or `rune::dev_tooling()`; `RUNE_PERF=1` still does in any build. Debug builds, and optimised ones that opt in, read flags and the endpoint exactly as before, and a list passed with `App::args` is Rune's in any build. A process argument that isn't valid UTF-8 now reaches `extra_args` with replacement characters instead of panicking. To drive an optimised build with Rune's flags, set `RUNE_DEV=1`, as the repo's benchmark, snapshot and motion-audit scripts now do; an app that needs to know whether Rune runs it headless asks `rune::is_headless()`, as the live-values, overlay, video-tiles and launcher examples now do. The rune README lists every `RUNE_*` variable.
